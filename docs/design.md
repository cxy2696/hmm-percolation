# 设计与取舍

这份文档记录“为什么代码长这样”。数学证明在 [mathematics.md](mathematics.md)，用法在 [usage.md](usage.md)，复现命令在 [reproduction.md](reproduction.md)。

## 1. 分层

```
core/     内存、错误、RNG、统计、CSV、日志
hmm/      离散 HMM、对角 GMM-HMM
perc/     并查集、CSR 图、格点、ER/配置模型、相关图
market/   面板、合成数据、特征、回测
cross/    转移矩阵阈值图（诊断用）
app/      走步重估、闸门、报告（C++17）
apps/     4 个 CLI
bindings/ Python / Julia
```

依赖只向下：`core ← hmm/perc/market ← cross ← app ← apps`，绑定只依赖 C ABI。金融相关的代码在 `market/` 和 `app/`；`hmm/`、`perc/`、`core/` 不知道“收益”“资产”这些概念。

## 2. 数值选择

### 2.1 只写 log 域

前向/后向全部用 $\log\alpha,\log\beta$，`logsumexp` 先减最大值。没有另写一套 scaled 算法。两套实现最后一定会在“概率恰好为 0”“序列特别长”“状态从未被访问”这些边界上分叉，测试成本翻倍。代价是 `log/exp` 比乘法慢，但当前规模（ $T\le3000,N\le5$）完全不是瓶颈。

### 2.2 对角 GMM

市场特征只有两维，且收益与波动高度相关。对角协方差：

- 天然正定，不需要 Cholesky 或特征值修复；
- M 步简单，方差下限可以直接加；
- 小样本下比 full covariance 稳。

代价是刻画不了“收益-波动”的联合尾部。如果以后要做多特征或更细的密度，扩展点在 `emission_row` 与 M 步的方差更新；接口不用改，模型文件加版本号。

### 2.3 初始化与状态排序

EM 只保证局部最优。`hp_ghmm_train` 的第 0 个起点按第一维特征排序切块，后面的起点用 Dirichlet 随机初始化。这样通常能把“弱/中/强”直接放到合理位置，随机重启只用来补漏。

训练完按混合均值排序，让状态 0 永远是期望收益最低的状态。排序不改变似然，但会让不同窗口的 `A`、`B` 可以对照。它不是可辨识性定理；标签置换仍然存在，只是被固定成一个约定。

### 2.4 下限与回滚

概率加 `1e-12`（离散）或 `1e-8`（GMM），方差加 `1e-4`。原因很实际：不加下限时，某个状态会收缩到单点，似然趋于无穷，EM 数值爆炸。

代价是严格的 EM 单调性证明不再逐字适用。代码每轮记录历史最优参数，若加下限后似然回退就回滚。测试里只做“多迭代不显著变差”的经验检查，不宣称严格单调。

### 2.5 配置模型：从 S 方程改成 q 方程

早期版本直接解

$$
S=1-\sum_k p_k(1-TS)^k.
$$

这个方程对 Poisson 度分布没问题，但对一般度分布不对：它把“邻居属于巨分量”的概率当成了 $S$，忽略了邻居度的尺寸偏置。取一半一度、一半三度的分布（ $T=1$），旧式给出 $S=1$；先解邻居灭绝概率的新式给出 $q=1/3$、 $S=22/27\approx0.8148$。这个例子已经写进测试。

现在解的是邻居灭绝概率

$$
q=\sum_k \frac{k p_k}{\mu}(1-T+Tq)^{k-1},
$$

再算

$$
S=1-\sum_k p_k(1-T+Tq)^k.
$$

阈值仍然是

$$
R_0=T\frac{\langle k(k-1)\rangle}{\langle k\rangle}\gt 1.
$$

对 Poisson， $q=1-S$，两式退化为熟悉的形式。

这仍然是树近似。 $T=1$ 且存在大量二度链时，环会让它高估 $S$。代码注释和 [mathematics.md](mathematics.md) 都写明了这一点；有限图的精确值要靠模拟，不靠这个函数。

## 3. 渗流指标

### 3.1 `theta_half` 而不是 `theta_peak`

相关图扫描时，`susceptibility` 的峰值在 $N=10$ 这种小图上经常落在平台或扫描边界。`theta_half` 是巨分量比例从 $\ge0.5$ 跌到 $\lt 0.5$ 的线性插值点，含义清楚：多数资产还在不在同一个连通块里。

`theta_peak` 仍写进 CSV，但只作诊断；策略闸门用 `theta_half`。

### 3.2 状态图阈值：从 $1/N$ 到中位数

最初把转移矩阵按 $1/N$ 阈值化，想用“巨分量是否覆盖全部状态”判断状态数。三状态模型的非对角转移只有 0.01–0.03， $1/3$ 把所有边都切掉，诊断永远报告三个孤立状态。这个阈值没有信息。

改成非对角元素的中位数：保留“较强的一半边”。三状态模型得到一个连通分量，五状态模型也是。它仍然只是诊断，不是选阶器；BIC 和走步样本外才是选阶依据。

### 3.3 60 日窗口与 80% 分位

60 日大约一个季度，能覆盖一段相关结构，又不至于太慢。30 日更敏感，但噪声更大；在这份合成样本上 30 日的闸门结果略差。80% 分位让闸门只在“比过去大多数时候更黏”时触发，样本外触发率约 12%。至少 120 个历史点才启用，避免早期样本不足。

这些参数没有做完整网格，也没有多市场稳健性。真实数据上应该滚动选择，而不是固定。

## 4. 回测

### 4.1 时序

`signal[t]` 在 t 日收盘后确定，作用于 `ret[t+1]`。换手成本按 `|signal[t]-signal[t-1]|` 计，初始建仓也收费。

### 4.2 样本外起点

第一个样本外决策在 `train_end` 收盘做出，所以第一个样本外收益日是 `train_end+1`。`metrics.json` 的 `oos_start` 指后者。

早先版本从 `train_end-1` 开始切片，等于用最后一天训练信号去赚第一天样本外收益。差别只有一天，但那是样本内信号，不应该算进 OOS。这个问题在 `tests/test_app.cpp::test_regime_no_lookahead` 之外又单独核对过。

### 4.3 仓位映射

三状态固定为 `0.1 / 0.55 / 1.0`。这是 long-only 的总仓位，不做空、不加杠杆。选择 0.1 而不是 0 是为了避免状态误判导致完全踏空；真实组合还要叠加行业、个股和容量约束。

## 5. 可维护性

### 5.1 C ABI

C 头文件不出现 C++ 类型；所有导出函数 `extern "C"`。C++ 应用层用带函数指针 deleter 的 `unique_ptr` 管理 C 对象。Python/Julia 只镜像公开结构体，不复制算法。

### 5.2 模型文件

文本格式，带版本行：

```
hp-hmm 1
states 3
symbols 3
pi ...
a ...
b ...
```

加载时检查维度、行和、方差为正。升级格式时改版本行，`load` 按版本分派；不要静默改字段顺序。

### 5.3 测试

- C：暴力路径、Viterbi、滤波、EM、恢复、BIC、IO、格点、已知 $p_c$、ER、相关图、回测时序。
- C++：JSON、连通性确定性、无前视、pipeline 确定性。
- Python/Julia：ABI、布局、与 C++ 模型 logL 的对照。

测试不依赖网络。`data/` 和 `out/` 里的文件是固定种子的产物，可以重新生成。

### 5.4 版本与发布

当前 0.1.0，API 还可能变。发布前：

1. `make clean && make -j && make check`；
2. `make python-test`，Julia 测试；
3. `scripts/reproduce.sh`，检查摘要数字；
4. 更新 `CHANGELOG.md`；
5. 打 tag，附上 `out/` 的摘要。

## 6. 不做什么

- 不做 full-covariance GMM：当前数据不需要，维护成本大于收益。
- 不做网络化 HMM：需要图上的消息传递和可解性分析，和当前“相关图闸门”不是一回事。
- 不做 FK/Potts：它是理论背景，不是这套代码的组件。
- 不接实时行情、不下单、不做组合优化。
- 不声称解决了 HMM 可辨识性或 EM 全局收敛。

## 7. 如果继续做

优先级从高到低：

1. 真实数据的复权、停牌、交易日对齐与缺失处理；
2. 多市场走步与参数稳健性；
3. 把配置模型的树近似与有限图模拟的差异量化；
4. 给状态数选择加一个走步准则，而不是只看 BIC；
5. 如果要扩特征，再做 full-covariance GMM。
